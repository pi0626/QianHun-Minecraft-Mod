【2】许愿系统
--------------------------------------------------------

2.1 前置
    书已唤醒（说出真名"千魂书"）   原著 L6473
    千魂计数 ≥ 1000              用户决策 5
    两条全满足才可许愿

2.2 流程
    GUI 输入愿望
    送 AI（OpenAI 兼容接口，模型名在配置里）
    AI 返回 JSON：{"commands":["...","..."]}
    逐条校验黑名单
    以服务器最高权限执行（op level 4，忽略游戏模式与玩家权限）
    许愿者血量置为 1

2.3 命令协议
    请求：system prompt 要求只输出 JSON，禁止解释
    返回：commands 数组，可 1 条也可多条
    容错：非 JSON 则整段拒绝；单条命令必须 / 开头
    上下文：附玩家名、坐标、维度、游戏模式、当前阈值状态，
            便于 AI 生成可执行命令

2.4 黑名单（默认开启，可配置关闭）
    /stop /op /deop /ban /ban-ip /pardon /pardon-ip /kick
    /whitelist /save-off /save-all /reload /shutdown

2.5 代价
    执行后 HP 置 1。已为 1 则不变。不致死。

【3】游尸（依原著）
--------------------------------------------------------

3.1 原著依据
    触发：因这本书死掉的那些人都会复活            L2500
          岛上那些游尸是独臂人前两年杀掉的可怜家伙 L7724
          即：与千魂书相关的死亡 → 复活为游尸
          非"神选夜才出现"，是"因书而死就复活"
    外观：复活后不保留致死时的样子
          （张昭辉被吊死，复活后不是吊死的样子）   L4641
          → 正是"照搬该实体正常模型"的原著依据
    表现：呆滞、僵硬、漫无目的地游走、蹒跚机械、
          只有轻微晃动、不攻击人                 L6108/L6749/L7202
    眼睛：模糊一团，没有黑白分明                 L6811
    气味：恶臭，挥之不去                         L6743/L7202
    消散：太阳升起后全部消失                     L7724

3.2 v3 规则（原著 + 用户要求合并）
    入池条件（满足其一即入游尸池）
        a 实体被玩家击杀                         用户要求
        b 实体死于 AI 许愿生成的命令              原著 L2500
    入池内容
        实体类型 ID
        若为玩家，另存其皮肤 profile
    生成时机
        死亡后当夜生成 1 只游尸，位置为死亡点附近
    消散
        日光升起后消失（原著 L7724 保留）
        可配置关闭
    上限
        同类型游尸同时存在数量可配置，默认 8

3.3 外观 = 照搬模型 + 压暗
    本体：被击杀实体的正常模型
    叠加：整体压暗为深灰黑调
    玩家形态：眼白压暗，眼窝加深（对应 L6811 眼睛模糊）
    兜底：类型无渲染器时退回内置人形游尸模型

【4】技术方案
--------------------------------------------------------

4.1 工程
    qianhun_1211/   MC 1.21.1  Fabric Loader 0.19.5
                    Fabric API 0.116.17+1.21.1
                    Loom 1.17-SNAPSHOT  插件 id net.fabricmc.fabric-loom-remap
                    Java 21  官方映射
    qianhun_262/    MC 26.2    Fabric Loader 0.19.5
                    Fabric API 0.161.0+26.2
                    Loom 1.17-SNAPSHOT  插件 id net.fabricmc.fabric-loom
                    Java 25  无 mappings 声明
    两者 Gradle 均为 9.5.1，均开 splitEnvironmentSourceSets

    已在官方模板实测确认的关键差异：
      1.21.1 用 fabric-loom-remap + modImplementation
      26.2   用 fabric-loom      + implementation
      26.2 build.gradle 无 mappings 行

4.2 工具链（本机原本无 Java，已在工作区内自建，不碰系统目录）
    tools/jdk/jdk-21.x     JDK 21（Temurin，编译 1.21.1）
    tools/jdk/jdk-25.x     JDK 25（Temurin，编译 26.2）
    tools/gradle-9.5.1     Gradle 发行包
    Python venv + Pillow 12.3.0  生成像素纹理

4.3 游尸渲染：幽灵实体代理
    服务端游尸 NBT 存 source_type / source_profile
    客户端为每只游尸建对应类型幽灵实体
    逐 tick 同步位置、朝向、肢体摆动
    调原版渲染器绘制，RenderSystem.setShaderColor 压暗
    已知风险：玩家幽灵需 profile；26.2 RenderState 与 1.21.1 不通用；
              部分自定义渲染层不吃 shader color
